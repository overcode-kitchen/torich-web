### A-6-2. 가설 (B) 번들 웹뷰 오리진 — **유력, 미확정**

`capacitor.config.ts`에 `iosScheme` 설정이 없어 **iOS 오리진이 기본값 `capacitor://localhost`** 다. 비-http(s) 커스텀 스킴이라 GA4가 `client_id`를 담을 쿠키를 쓸 수 없다.

**정황**:
- 4개월간 **번들 오리진(`capacitor://localhost`)에서 온 히트가 두 속성 어디에도 0건**
- 반면 같은 앱을 `http://` 오리진(라이브리로드 사설 IP)으로 띄우면 **정상 수집된다** — 위 표의 `Safari (in-app)` 행들이 그 증거
- 즉 **앱 코드가 아니라 오리진이 변수**라는 대조군이 이미 데이터에 있다

**확정 방법** (→ #110, v1.5.0): 개발 빌드 실기기 + Safari 웹 인스펙터로
`location.origin` / `googletagmanager.com/gtag/js` 상태코드 / **`/g/collect` 요청 발생 여부**.
`gtag/js`는 200인데 `/g/collect`가 없으면 오리진 문제 확정.

**해결책 후보와 부작용**:

| 방법 | 효과 | 부작용 |
| --- | --- | --- |
| `server.iosScheme: 'https'` | 오리진이 `https://localhost`가 되어 GA 정상화 기대. 가장 간단 | ⚠️ **오리진이 바뀌면 기존 앱의 localStorage·쿠키가 새 오리진으로 분리된다.** 운영 중인 로그인 세션이 풀리고 로컬 저장값이 초기화될 수 있어, 마이그레이션 없이 바꾸면 안 된다 |
| Measurement Protocol 직접 전송 | 오리진 무관하게 동작. 이미 `notification_sent` Edge Function에서 쓰는 방식 | 자동 수집 이벤트(`page_view`, `session_start` 등)를 직접 구현해야 함 |
| Firebase Analytics 네이티브 플러그인 | 가장 정석 | 작업량이 큼 |

> **우선순위**: 앱 실사용자가 거의 없어 계측을 고쳐도 당장 볼 데이터가 없다. v1.5.0 일정으로 충분하다.

### A-8-1. 코드 조사 결과 — **우선순위 내림**

`app_error`를 쏘는 곳은 `app/error.tsx:44` **한 곳**뿐이고, 싣는 파라미터는 둘뿐이다.

```ts
track('app_error', {
  message: type ?? 'unknown',                 // 'network' | 'server' | 'unknown' 3분류
  ...(error?.digest ? { digest: error.digest } : {}),
})
```

`message`는 이름과 달리 원본 메시지가 아니라 `getErrorTypeFromMessage()`가 3개 버킷으로 뭉갠 값이다 → **PII 위험 없음. 동시에 맞춤 측정기준으로 등록해도 얻을 정보가 얇다.**

발생 시점이 개발 일정과 정확히 겹친다: 7/22(11) 목적 카드 롱프레스·마감일 시트 / 7/24(16) 홈 상태 승격·통계 집계 / **7/28(20) 통계 3탭 전면 개편(커밋 15개)** / 7/30(6) 후속 피드백.

**→ 손님이 겪은 에러가 아니라 개발 중 직접 밟은 에러다.** Prod 속성의 `app_error`는 **0건**이고, 8/13~8/19에 `fix(stats)`·`fix(investment)`·`fix(goal)` 커밋이 15건 넘게 들어가 상당수가 이미 해소됐을 것으로 본다. **`error_type` 맞춤 측정기준 등록은 하지 않는다.**
