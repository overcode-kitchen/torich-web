# 목적 추가 플로우 UX 방향성

> 레퍼런스 앱(미국 주식 적립 서비스) 비교 분석을 바탕으로 도출한 토리치 플로우 화면 설계 원칙.
> 목적 추가(goal/new) 뿐만 아니라 적금·투자 추가 등 모든 "입력 → 저장" 플로우에 동일하게 적용한다.

---

## 핵심 철학: "폼지 작성"이 아닌 "결정 확인"

기존 폼 UI는 필드를 채우는 행위가 목적이다 — 사용자는 빈칸을 채워 나간다.
목표 방향은 사용자가 **"내가 이걸 하기로 결정했다"는 확신감**을 느끼며 화면을 넘기는 경험이다.

---

## 5가지 설계 원칙

### 1. 타이포그래피 — 제목이 주인공

| | 이전 | 방향 |
|---|---|---|
| 스텝 제목 | `text-lg font-semibold` (18px) | `text-2xl font-bold` (24px+) |
| 느낌 | 서브 헤더, 존재감 없음 | 화면을 지배하는 대화체 질문 |

**규칙**: 플로우 화면의 질문 제목은 항상 `text-2xl font-bold tracking-tight` 이상.
디자인 시스템 H3 (`text-2xl font-semibold`) 를 최소 기준으로 삼는다.

---

### 2. 맥락 주입 — 사용자 입력을 제목에 되돌려준다

이전 스텝에서 입력한 값을 다음 스텝 제목에 반영해 **개인화된 대화** 느낌을 준다.

```
// 이전
"얼마를 모으려고 하나요?"

// 방향
"결혼자금, 얼마나 모을까요?"  ← 앞 스텝에서 입력한 이름 주입
```

패턴: `${goalName ? `${goalName}, ` : ''}질문 본문`

---

### 3. 입력값 히어로 — 입력 필드가 아닌 입력값이 빛나야 한다

사용자가 숫자를 입력하면 그 값이 화면에서 가장 크게 보여야 한다.
"내가 5,000만원을 모으기로 했다"는 느낌을 시각적으로 강화.

```
// 이전: 일반 input 박스 (text-base)
[ 5,000               만원 ]

// 방향: 대형 입력 (text-3xl font-bold, text-center, h-16)
[       5,000       만원   ]
        ↑ 크고 대담하게
```

**규칙**: 금액·수량 입력 필드는 `text-2xl` 이상 + `text-center` + 충분한 `h-*`.

---

### 4. CTA 문구 — 기능 설명이 아닌 결정 확인

| | 이전 | 방향 |
|---|---|---|
| 중간 스텝 | "다음" | "다음으로" |
| 마지막 스텝 | "목적 만들기" | "이대로 만들기" |

"이대로"는 "내가 입력한 이 값으로"라는 뉘앙스 — 사용자의 결정을 존중·확인하는 어투.
레퍼런스: "이대로 모으기".

---

### 5. 여백 — 밀도를 낮춰 숨통을 트여라

플로우 화면은 정보 밀도를 낮게 유지한다.

- 제목과 첫 번째 요소 사이: `mb-8` 이상
- 주요 섹션 간 간격: `gap-6` ~ `gap-8`
- 한 스텝에 노출되는 인터랙션 요소: **3개 이하** 권장
  - Step A(이름)의 프리셋 칩 그리드는 허용 — 단순 선택지이므로 밀도 예외

---

## 플로우 화면 신규 작업 시 체크리스트

- [ ] 스텝 제목이 `text-2xl font-bold` 이상인가?
- [ ] 이전 스텝 입력값을 현재 스텝 제목에 반영했는가?
- [ ] 금액/수량 입력 필드가 `text-2xl` 이상으로 충분히 크게 표시되는가?
- [ ] 마지막 스텝 CTA가 "이대로 ~" 패턴인가?
- [ ] 한 화면에 인터랙션 요소가 4개 이상 몰려 있지 않은가?
