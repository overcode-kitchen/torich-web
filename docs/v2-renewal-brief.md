# 토리치 v2.0.0 리뉴얼 브리프

> [!abstract] 한 줄로
> **"매달 투자, 까먹지 않게" 앱을 "1억 모으기" 앱으로 다시 만든다.**
> 기능을 더 얹는 게 아니라, **한마디로 설명되는 앱**으로 좁히는 작업이다.

이 문서는 2026-08-20 ~ 08-21에 정한 것을 한 곳에 모은 것이다.
**결정 배경**은 [idea-log.md](idea-log.md), **일정**은 [direction-shift-plan.md](direction-shift-plan.md),
**남은 결정**은 [phase2-checklist.md](phase2-checklist.md), **화면**은 [IA 캔버스](https://claude.ai/code/artifact/7fb4247b-c6e4-4ed0-910d-ecf3eb686172)에 있다.

---

## 1. 왜 바꾸는가

몇 달을 만들어 1.0.0에서 1.4.0까지 왔는데 **앱스토어 노출이 월 1회**다. 홍보는 0회.
진단은 셋이었다.

- **카피가 차별점이 아니다.** "매달 투자, 까먹지 않게"는 캘린더 알림으로도 되는 일이다
- **검색어가 없다.** 사람들은 "필요 → 검색 → 설치" 순으로 움직이는데, **토리치는 뭐라고 쳐야 나오는지** 우리 둘 다 답을 못 했다
- **입력 플로우가 만드는 사람도 헷갈린다.** 투자/예적금/현금으로 나뉜 뒤 종류마다 묻는 게 다르다

그래서 **기능을 더 만드는 걸 멈추고, 사람이 찾아올 이유를 먼저 만들기로** 했다.

## 2. 컨셉 — 1억 모으기

> [!success] 주기능은 하나다
> **"나는 1억까지 얼마나 왔는가"**를 보여주고 알려주는 **베이스캠프.**

| 항목 | 확정 |
| --- | --- |
| **주기능** | 1억 모으기 |
| **타겟 한 문장** | 1억을 모으려는 사람이 쓰는 앱 |
| **메인 타겟(1차)** | **이미 모으는 방법을 갖췄고, 우리 걸로 기록하러 온 사람** |
| 2차 타겟 | 이제 시작하려는 사람. 1차를 먼저 만든 뒤 붙인다 |
| **버리는 컨셉** | "목적 기반으로 모으는 걸 도와준다" |

**흩어진 적립을 한 화면에서 보는 것은 주기능이 아니라 수단이다.** 1억을 모으려면 흩어진 걸 봐야 하니 자연히 따라온다.

**"목적 기반"은 우리가 시작한 지점이지만, 그게 앱이 복잡해지고 한마디로 설명 안 되는 원인이었다.** 그래서 폐기한다. 1억 달성 후에는 **"다음 1억"**으로 카운터가 다시 0부터 간다 — 목표는 늘 하나다.

> [!note] 메인 타겟이 설계를 결정한다
> 1차 타겟에게 "목적을 만드세요"부터 시키면 **옮겨 적으러 온 사람에게 기획을 시키는 것**이다.
> 첫 화면은 **가르치는 화면이 아니라 받아 적는 화면**이어야 한다.

## 3. 화면 구조

**탭 4개 → 3개.** 통계는 탭에서 빠져 홈의 하위로 내려간다.

| 탭 | 무엇이 있나 |
| --- | --- |
| **홈 `/`** | ① 1억 진행률 ② 이번 달 할 일(그 자리에서 체크) ③ 적립 항목 목록 ④ 이번 달 완주 축하 |
| **기록 `/calendar`** | **달력이 아니라 장부** — 회차 목록 · 빈 달 채우기(소급) · 월별 채움 요약 |
| **설정 `/settings`** | 목표 금액 · **시작 잔액** · 알림 · 테마 · 계정 |

**홈 아래로 내려가는 것**

- `/add` 적립 항목 담기·고치기
- `/item?id=` 항목 상세 (넣은 기록 · 1억 기여도)
- `/detail` **자세히 보기 — 지금 9섹션을 3섹션으로** (자산 추이 · 월별 납입 · 도달 예측)
- 알림함(시트) · 알림 상세 · 약관/개인정보/FAQ

**통계를 탭에서 뺀 이유**: 통계는 숫자를 움직이지 않는다. 1억을 실제로 올리는 행동은 납입 체크뿐이다.

**기록 탭은 달력에서 장부로 성격을 바꾼다** **(확정)**. 원래 근거는 *"언제 얼마를 넣기로 했나는 달력 없이 안 보인다"*였는데, 이번 재설계로 그 일이 **홈의 '이번 달 할 일'**로 옮겨갔다. 지난 기록은 `/detail`의 월별 납입이 답한다. 그러면 달력에 남는 일은 하나뿐이다 — **채운 것과 빈 것을 보고 메우는 것.** 소급을 기간 제한 없이 살렸으므로 그 입구가 여기다. 그래서 월 그리드는 상단 요약으로 줄이고 **회차 목록**을 본체로 둔다.

## 4. 핵심 플로우

### 첫 진입 — 목표는 "첫 진행률을 보게 하는 것"

```
랜딩 → 로그인 → 목표 금액(1억 기본)
     → 지금 얼마나 모였나 (스톡)      ← 캡처로 읽어오거나 직접 입력
     → 매달 얼마나 모을 수 있나 (플로우) ← 월급이 아니라 "떼어놓을 수 있는 돈"
       (또는 "언제까지 모으고 싶나" — 둘 중 하나만 받으면 나머지가 계산된다)
     → 홈 (이미 30% · 2033년 5월 도착)
     → 적립 항목 담기
```

**두 가지를 다 받는 이유**: 모은 돈(스톡)만 알면 **"얼마나 왔는지"**밖에 못 말한다.
매달 얼마씩 모으는지(플로우)를 알아야 **"언제 도착하는지"**를 말할 수 있다.
소득은 묻지 않는다 — 월급 400만원인 사람이 50만원을 모을 수도 200만원을 모을 수도 있어 **앞의 숫자는 쓸모가 없다.**
이 답은 나중에 실제 적립액과 비교할 **기준선**이 되고, **건너뛸 수 있다.**

**목표 시점은 마감일이 아니다** **(확정)**. `매달 얼마`와 `언제까지`는 같은 식의 양변이라 **하나만 받으면 나머지가 나온다.**
안 정하면 도착일을 예측해 말하고, 정하면 필요 월 적립액을 말한다.
**D-day도 빨간 미달 표시도 만들지 않는다** — 못 지켜도 아무 일이 안 일어나고 **"5개월 밀렸어요"까지만** 말한다.

**순서가 바뀐 게 제일 큰 변화다.** 기존은 `홈 0원 → 항목 추가 → 0.4%`였다.
이제 **시작 잔액을 먼저 받아 홈이 30%로 열린다** — 아무것도 입력하기 전에 숫자가 차 있다.
메인 타겟이 "이미 모은 사람"이면 이 순서여야 한다.

**목적 만들기 단계는 없다.**

### 계획이 먼저 있고, 항목이 그걸 채운다 **(확정)**

온보딩에서 받은 "매달 100만원"은 **기준선으로만 두고 버리는 숫자가 아니다.** 항목 담기의 기준이 된다.

```
온보딩   "매달 얼마나 모을 수 있어요?"  →  100만원          ← 계획
              ↓
항목 담기   이 100만원을 무엇으로 채울까?
            청년적금 40만 · S&P500 40만 · 비상금 20만
              ↓
홈        매달 100만원 모으는 중  ▓▓▓▓▓▓▓▓▓▓
          지금 페이스면 2033년 5월
```

**지금은 순서가 반대다** — 항목을 다 담고 나서야 매달 얼마인지 알 수 있다.
계획을 먼저 두면 **"40만원 남았어요"가 항목을 더 담을 이유**가 되고, 홈의 '이번 달 할 일'이 왜 그것들인지도 설명된다.
계획을 **건너뛴 사람은 항목 합계가 곧 계획**이 된다.

**도달 예측은 계획으로 계산한다** — 실제 납입 평균으로 몰래 낮추지 않는다.
그러면 **내가 정한 목표가 나도 모르게 깎인다.** 계획을 바꾸는 건 사용자뿐이고, 앱은 **권하기만** 한다.

```
3개월째 계획보다 30만원 덜 넣고 있어요.
계획을 70만원으로 고칠까요?        [고치기]  [그대로 둘게요]
```

**계획의 20% 이상이 3개월 연속** 어긋났을 때만 묻는다 — 매달 물으면 잔소리다.
**더 넣는 쪽도 같이 본다**("계획을 올릴까요?"). 항목이 만기로 끝나 계획에 구멍이 나면 그때도 같은 방식으로 묻는다.

### 매달 루프 — 1억을 실제로 움직이는 유일한 행동

```
납입일 알림 → 홈 '이번 달 할 일' → 체크(탭 1회) → 진행률이 그 자리에서 오른다
```

**알림에서 체크까지 탭 2회.** 지금은 `홈 → 목적 카드 → 적립 항목 → 체크`로 4회다.
**이 루프의 길이가 이번 재설계의 성공 지표다.**

## 5. 자산 불러오기 — 연동이 막혀서 스크린샷으로 간다

> [!danger] 2026-08-21 기술 검토 결과
> **사업자가 아니라 금융 연동을 쓸 수 없다.**
> 마이데이터는 금융위 허가 사업자만 가능하고, 오픈뱅킹도 이용기관 등록이 필요하다.

### 대신: 사용자가 쓰던 앱 화면을 받아 대신 적어준다

```
권하기(예시 먼저) → 앨범에서 고르기 → 처리 중(단계 표시) → "이거 맞나요?" → 홈에 반영
```

**가이드가 버튼보다 위에 온다.** "화면 캡처로 불러오기"만 있으면 뭘 찍을지 모른다.
**최근 스크린샷을 맨 앞에** 띄운다(방금 찍고 돌아온 사람이 대부분이다).
**처리 중에는 단계를 보여준다** — 돌아가는 원 하나만 있으면 멈춘 것처럼 보인다. 이 몇 초가 신뢰를 만든다.

토스·뱅크샐러드 같은 곳의 **자산 목록 화면을 캡처**해 올리면, **비전 모델이 항목명과 금액을 읽어** 목록으로 만들고, 사용자가 **확인·수정한 뒤** 저장한다.

### 순수 OCR이 아니라 비전 모델을 쓴다

| | 한계 / 강점 |
| --- | --- |
| 순수 OCR | **글자는 읽지만 구조를 모른다.** 어느 숫자가 어느 항목의 금액인지, 뭐가 합계인지 규칙으로 짜야 하는데 앱마다 화면이 달라 계속 깨진다 |
| **비전 모델** | 이미지를 넣고 **항목명·금액 목록을 JSON으로 바로** 받는다. 화면이 달라도 대응하고 **확신도까지 받아** "읽기 애매함" 표시에 쓴다 |

**돌릴 곳은 이미 있다.** Next.js API Route(Vercel)로 사진을 보내 파싱하고 JSON만 돌려받는다.
사진 고르기는 `@capacitor/camera`. **새 네이티브 타깃이 필요 없다.**
비용은 이미지당 몇 원, 사용자당 1~3장이면 무시할 수준이다.

### 여기가 제일 위험한 구간이다

- **사진을 저장하지 않는다.** 읽고 즉시 버린다
- **계좌번호·이름·주민번호는 애초에 읽지 않는다.** 항목명과 금액만
- 그 사실을 **사진을 고르기 전에** 화면에 쓴다
- **개인정보 처리방침을 반드시 고친다** — 이미지 업로드와 외부 처리 위탁이 새로 생긴다
- **타사 앱 이름을 우리 화면에 크게 쓰지 않는다** — 제휴로 오해될 수 있다

### 성격을 오해하면 안 된다

> [!warning] 이건 연동의 대체가 아니라 **수동 입력의 가속기**다
> 항목이 서너 개면 **손으로 치는 게 더 빠르다.** 앱을 나가 캡처하고 돌아오는 것보다 금액 세 번 치는 게 짧다.
> **항목이 많은 사람에게만 이긴다.** 그래서 필수 경로로 두지 않고, **"직접 입력할게요"가 늘 같은 크기로 옆에 있다.**

**손으로 넣는 길이 기본 경로다.** 정확도를 요구하지 않고("나중에 고칠 수 있어요"를 먼저 말한다), 날짜를 찍게 하지 않고(횟수·개월수로 받아 역산), 0을 세게 하지 않는다(+100만 칩). **중복은 우리가 찾아준다** — 수기 항목과 읽어온 항목이 같은 계좌인데 안 잡으면 **1억이 두 배로 뻥튀기된다.**

## 6. 입력 방식 — 한 화면에 한 질문

토스 입력 흐름을 레퍼런스로 삼았다. **가져온 것은 방식뿐이고 색·타이포·비주얼은 토리치 것으로 입힌다.**

```
무엇을 모으고 있나요? → 얼마씩 넣나요? → 언제마다? → 언제부터? → 확인 → 완료
```

- **질문이 곧 제목이다.** 필드 위 작은 라벨 대신 화면 제목이 문장으로 묻는다
- **키보드는 이미 올라와 있다.** 다음 버튼은 키패드 바로 위에 붙어, 답하기 전엔 흐리게 보인다
- **치는 동안 결과가 보인다** — 금액을 치면 즉시 **`1억까지 +0.4%`**
- **계획을 얼마나 채웠는지 같이 보인다** **(확정)** — `매달 100만원 중 60만원 채움 · 40만원 남음`
- **필수는 4개**(이름·금액·주기·시작 시점). 종목·주수는 **선택으로 내리고, 만기일은 아예 묻지 않는다** **(확정)**
  — 유형을 없애 적금인지 ETF인지 앱이 모르므로 물으려면 모두에게 물어야 한다. **도달 예측을 최근 3개월 실제 평균으로 내면 만기를 몰라도 자동으로 따라잡는다**
- **유형(투자/예적금/현금)을 먼저 묻지 않는다.** 입력 규칙은 하나로 통일한다 **(확정)**
- **종목 검색·주수는 남긴다** **(확정)** — ETF는 금액이 아니라 **주 단위로 사는 물건**이다. 종목을 고른 뒤에만 주수·시장이 나타나고, 시장·평단가는 **묻지 않고 계산한다**
- **금리·만기일은 선택 필드로 내린다** **(확정)** — 예적금 쓰는 사람에겐 실제 정보다. 안 물어도 되게만 만든다

**드는 동작: 타이핑 2번 + 탭 4번.** 지금은 유형 선택부터 시작해 그 두 배가 넘는다.

## 7. 축하 — 오는 주기가 다르면 연출의 무게도 다르다

| 주기 | 무엇 | 연출 |
| --- | --- | --- |
| **매달** | 그 달 할 일을 다 채운 순간 | **1초 안쪽.** 도토리 1알 + **"여섯 번째 달"**(누적) + 쌓인 도토리 |
| **1천만원 단위** | 드물게 | **손으로 문질러 도토리를 칠한다** |
| **1억** | 4년에 한 번 | **토리가 정지 화면 네 장으로 말을 건다** |

**매달이 없으면 큰 세리머니는 평생 몇 번밖에 안 온다.** 매달이 리듬을 만들고 1천만원이 사건을 만든다.

**연속이 아니라 누적을 센다** **(확정)**. "3개월 연속"은 한 달만 걸러도 0으로 리셋돼
다섯 번 넣은 사람에게 "1개월"이라고 말한다 — **정의상 못 채운 달을 벌주는 장치**라
바로 아래 원칙과 어긋난다. 그래서 **"여섯 번째 달"**처럼 줄어들지 않는 수를 쓴다.

매달 축하에 **누적 개월과 쌓인 도토리가 없으면 그냥 팝업**이다. 축하가 아니라 **누적**이 매달을 살린다. 빈 달은 회색 실패로 칠하지 않고 옅은 점선으로만 둔다 — **못 채운 달을 벌주는 화면이 되면 안 온다.**

**1억 달성 문구 방향**

> 1억. 4년 2개월 걸렸네요. → 이 돈이 무엇이 될지는 아직 아무도 몰라요. → 가족이 아플 때, 잠깐 쉬어야 할 때, 하고 싶은 게 생겼을 때. → 돈이 전부는 아니지만 그때 곁에 있어 줄 거예요. 계속 모아볼까요?

가르치지 않는다(투자 조언 금지) · 금액을 다시 말하지 않는다 · **건너뛸 수 있다**(감동을 강제하면 반대가 된다).

**그 밖에 좋은 말을 건넬 자리**: 처음 담은 날 · 한 해가 바뀔 때 · 한 항목 12회 · 도착일이 당겨졌을 때.
고르는 기준은 **자주 오고, 값이 싸고, 부끄럽지 않고, 혼내지 않는 것.**

## 8. 공유 — 금액을 내보내지 않는다

> [!important] 홍보 자산이 성립하는 조건
> **서른에 1억을 못 모은 건 부끄러울 수 있는 일이다.**
> 금액이나 진행률을 담은 카드는 **공유될 수 없는 홍보 자산**이고, 만들어도 아무도 안 올린다.

**역산되는 것도 안 된다.** "10칸 중 4칸"은 4천만원이고 "32%"는 3,200만원이다. 단위를 아는 순간 금액이 된다. → 도토리 컬렉션에서 **전체 칸 수를 보여주지 않는다.**

공유 카드가 담는 것은 **지속과 자기가 칠한 그림**뿐이다 — **"여덟 번째 달을 다 채웠어요"**. 이건 부자든 아니든 자랑할 수 있다.

**언제 권하는가도 설계다.** 공유 버튼을 홈에 상시로 두지 않고, **완주·칠하기처럼 스스로 잘했다고 느낀 직후**에만 조용히 내민다. 못 채운 달에는 꺼낸다.

## 9. 무엇을 버리는가

> [!warning] 서랍에 넣지 않는다
> "일단 숨겨두자", "상세 설정으로 접자"는 문제를 미루는 것이다.
> 각 기능에 던지는 질문은 **"이게 왜 필요한가"**이지 "어디에 둘 것인가"가 아니다.

판정 기준은 하나 — **"1억 모으기를 돕는가."**

### 판정 결과

| 대상 | 판정 | 근거 |
| --- | --- | --- |
| **목적(goals)** — 화면 4개 | **삭제** | 목표가 1억 하나면 계층 자체가 사라진다. **태그로도 남기지 않는다** |
| **목적 프리셋** | **삭제** | 목적에 종속. 계층이 사라지면 근거도 사라진다 |
| **토리 키우기** — 파일 34개 | **삭제** | 진입 경로가 없어 사용자에겐 이미 없는 기능. **브랜드 스토리와 파일이 섞여 있어 분리해서** 지운다 |
| **투자/예적금/현금 3분류** | **유형 질문만 삭제** | 유형을 먼저 묻지 않는다. **종목 검색·주수·금리·만기일은 선택 필드로 남긴다** (§6) |
| **소급 기록** | **존치** | 과거 회차를 넣을 수 있어야 한다. 시작 잔액 한 줄로 대체하지 않는다 |
| **알림 7종** | **v2.0.0에서 손대지 않음** | 매달 루프의 **시작점**이고, 계측 0건이라 줄일 근거가 없다. 문구만 1억 기준으로 고친다 |
| **FAQ · 브랜드 스토리** | **존치 · 내용 교체** | 페이지는 필요하다. 지금 내용이 목적·3유형 기준이라 **그대로 두면 없는 기능을 설명하게 된다** |
| **`/design-system`** | **존치** | 컴포넌트·토큰 점검용으로 실제로 쓴다. 앱에 링크가 없어 유지비 0 |
| **통계 23섹션** | **`/detail` 3섹션으로 축소 — 순서는 맨 뒤** | 삭제가 아니라 **재작성**이다. 카운터 기준이 정해져야 만들 수 있다 |
| **납입 연기** | **삭제** | 1억엔 마감일이 없어 "빠뜨림"이 사라지고, **못 넣은 달은 소급으로 채우면 된다.** 연속 기록을 **누적**으로 바꾸면서 연기가 하던 일이 없어졌다. **23개 파일이 통째로 빠진다** |

**목적 삭제로 새로 생긴 결정**: 목적별 마감일·목표금액을 버리는가 · 목적이 여러 개인 사용자의 합산 규칙 · FAQ 재작성(9월 카피 작업).

> [!danger] 데이터는 지우지 않는다
> 목적·토리 테이블은 화면에서 내리더라도 **컬럼 삭제 없이 남긴다.**
> 운영 앱에 구버전이 살아 있고 스키마 변경은 곧 Breaking Change다.
> **화면 제거와 테이블 제거는 배포를 한 번 사이에 두고 나눈다.**

**기존 사용자 전환 안내 화면은 만들지 않는다** (기존 사용자가 거의 없다). 다만 목적별 금액을 하나의 1억으로 합치는 **데이터 마이그레이션은 필요하다.**
