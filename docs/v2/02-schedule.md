### Phase 2.5 — 스키마 + 삭제 (9/1~9/6) · 선이 주도

**화면이 어떻게 생기든 값이 같은 일**만 모았다. 와이어프레임을 기다리지 않는다.

| 무엇 | 내용 |
| --- | --- |
| 스키마 4건 | `user_settings` 5컬럼 · `payment_history.amount` · `is_skipped` · `record_type` 자동 판정 → [03-decisions §6](03-decisions.md) |
| 타입 재생성 | `supabase gen types typescript > types/database.types.ts` |
| 삭제 6종 | 목적(화면 4) · 토리 키우기(34파일) · 납입 연기(23파일) · 적립 항목 상세 · ETF · 기록 탭·소급 |
| 화면 내 금액 가리기 | 토글 UI만 제거 (컬럼은 남긴다) → [06-constraints §4](06-constraints.md) |
| 데이터 합치기 | 기존 기록을 전부 더해 `start_balance`에 넣는다 |

> [!warning] **삭제는 화면만, 테이블은 남긴다.** 운영 앱에 구버전이 살아 있어 컬럼 삭제는 Breaking Change다 ([CLAUDE.md](../../CLAUDE.md))

## 역할

**기획·설계는 둘이 같이. 실행만 나눈다.**

| | 무니(김영문) | 선이(현선) |
| --- | --- | --- |
| 기획 · 화면 설계 · 기능 판정 | 같이 | 같이 |
| 카피 | 주도 | 검토 |
| 구현 (Phase 2.5 · 3) | 검토 | **주도** |
| ASO · 스토어 · GA 콘솔 (Phase 4) | **주도** | 스크린샷 제작 |
| QA · 실사용 | 같이 | 같이 |

- **혼자 정하면 안 되는 것**: 새 화면, 새 필드, 기능 삭제, 카피 변경
- **혼자 해도 되는 것**: 버그 픽스, 리팩토링, 성능 개선
- 싱크: 스퍼트 기간(~9/30)은 **매일 저녁 15분**
