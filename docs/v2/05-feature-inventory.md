## 2. ★ 입력 규칙이 유형마다 다른 지점

> **선이 지적 ②·③의 실물이다.** 적립 항목을 만들 때 3그룹(A 무엇 → B 얼마 → C 언제)을 거치는데, **각 그룹의 질문이 유형마다 다르다.**

| 그룹 | **투자** (주식·ETF) | **예·적금** | **현금** |
| --- | --- | --- | --- |
| **A. 무엇을** | 종목 검색 + **시장 선택(KR/US)** | 항목 이름 직접 입력 | 항목 이름 직접 입력 |
| **B. 얼마를** | 매달 얼마 (**금액 or 주수 선택**) | 매달 얼마 | 매달 얼마 |
| B (추가) | 얼마나 오래 투자할까 (기간) | **약정 연이율(%)** | 얼마나 오래 모을까 (기간) |
| B (추가) | — | **만기일** | — |
| **C. 언제** | **시작일** + 매월 투자일(복수 선택) | 매월 날짜 | 매월 날짜 |
| 목적에 묶을 때 | 언제까지 모을까 (종료일) | 좌동 | 좌동 |

**질문 4개가 나온다.**

1. **투자만 "시작일"을 묻는 이유**가 있는가? (예적금·현금은 안 묻는다)
2. **투자만 "주수" 단위**를 지원하는 이유가 있는가?
3. **예적금만 "만기일"**을 갖는데, 그 만기일이 **목적 종료일을 넘어가면** 어떻게 되는가? → **현재 규칙 없음**
4. 사용자에게 **투자/예적금/현금 구분이 의미가 있는가?** 아니면 우리 데이터 모델 사정인가?

## 3. 데이터 모델 — `records` 24개 컬럼의 유형별 사용

**한 테이블에 3유형을 다 담고, 유형마다 쓰는 컬럼이 다르다.** 안 쓰는 컬럼은 `null`로 남는다.

| 컬럼 | 투자 | 예적금 | 현금 | 비고 |
| --- | :-: | :-: | :-: | --- |
| `title` | ● | ● | ● | 공통 |
| `record_type` | ● | ● | ● | 유형 구분 |
| `monthly_amount` | ● | ● | ● | 공통 |
| `goal_id` | ○ | ○ | ○ | 목적 연결 (없으면 null) |
| `sort_order` | ○ | ○ | ○ | 목적 카드 내 순서 |
| `notification_enabled` | ● | ● | ● | 항목별 알림 |
| `symbol` / `market` | ● | ✕ | ✕ | 종목·시장 |
| `unit_type` / `monthly_shares` | ● | ✕ | ✕ | 금액/주수 모드 |
| `start_date` | ● | ✕ | ✕ | **투자만** |
| `investment_days` | ● | ● | ● | 매월 납입일 (3유형 공통) |
| `period_years` | ● | ✕ | ● | 기간 |
| `annual_rate` / `is_custom_rate` / `rate_updated_at` | ● | ✕ | ✕ | 수익률 |
| `interest_rate` | ✕ | ● | ✕ | **예적금만** — 약정 금리 |
| `maturity_date` | ✕ | ● | ✕ | **예적금만** — 만기일 |
| `settled_at` | ✕ | ● | ✕ | **예적금만** — 만기 정산 |
| `final_amount` | ● | ● | ● | 구버전 호환용 잔존 컬럼. 예적금·현금은 `0` 고정 저장 |

● 사용 · ○ 선택 · ✕ 미사용(null)

> **한 테이블을 3유형이 공유하면서, 3유형 모두가 쓰는 건 8개뿐이다.** 나머지 16개는 유형 전용이거나 잔존물이다.
> 이 구조가 "가지를 만들어서 한 나무에 갖다 붙인 느낌"의 실체다.

- **알림 설정 변경** (7종) — 이벤트 0개

> 통계 화면에 계측이 9개로 가장 몰려 있다. **만드는 쪽의 관심이 통계에 가장 많이 갔다는 뜻**이고,
