# v2 새 화면 제약

> [!abstract] 이 문서가 겨누는 것은 **아직 안 그린 화면**이다
> 목적 카드·캘린더·ETF는 어차피 지워진다. 위험한 건 그게 아니라,
> **새로 그릴 홈에서 1억 카운터 옆에 뭐가 계속 붙는 것**이다.
>
> 이번 달 페이스 · 남은 개월 수 · 작은 스파크라인 · 도토리 미리보기 · 응원 문구 —
> 전부 "도움이 되어 보이는 것"이고, **브리프 어디에도 금지돼 있지 않다.**
>
> 사람은 개선을 요구받으면 **빼기를 거의 떠올리지 못하고**, LLM은 학습 데이터의
> 평균(대시보드 + 카드 + 차트)으로 수렴한다. 프롬프트로는 안 막힌다.
> 그래서 **상한과 금지 목록**으로 막는다. 취향의 기록이 아니라 **가드**다.

**판정 기준은 하나다.**

> **"이 요소가 없으면 사용자가 '1억까지 얼마나 왔고 오늘 뭘 해야 하는지'를 알 수 없게 되는가?"**

답이 "아니오"면 안 만든다. **"숨기기 / 설정으로 이동 / 나중에"는 선택지가 아니다** ([01-brief.md §9](01-brief.md) "서랍에 넣지 않는다").

---

## 1. 이 문서가 다루지 않는 것

**[01-brief.md §9](01-brief.md)가 이미 삭제로 확정한 것은 여기서 다시 판정하지 않는다.**
목적(goals) · 목적 프리셋 · 토리 키우기 · 유형 3분류 · ETF(종목·주수·시장) · 기록 탭(달력) · 소급 기록 ·
적립 항목 상세 화면 · 수동 체크 · 납입 연기 — **결정은 끝났고, 이 문서는 그 위에서 시작한다.**

여기 적는 것은 **브리프가 침묵하는 지점**, 즉 새 화면을 그릴 때 아무도 막지 않는 것들뿐이다.

---

## 2. 요소 예산

**세는 단위**

- **블록** = 시각적으로 구분되는 카드·섹션·바 1개 (`bg-card` 껍데기, 구분선으로 나뉜 영역, 고정 바)
- **숫자** = 화면에 렌더링되는 수치 1개 (금액·%·개월·건수·날짜의 숫자 부분). 목록의 반복 항목은 **행당 상한**으로 따로 센다
- 상한은 **동시에 보이는 최대치**다. 조건부로만 뜨는 것도 뜨는 순간엔 카운트된다

| 화면 | 블록 | 숫자 | 차트 | primary 버튼 | 비고 |
| --- | --- | --- | --- | --- | --- |
| **홈 `/`** | **4** | **2** + (항목행당 1) | **0** | **1** | 블록 4 = 카운터 · 이번 달 현황 · 항목 목록 · 축하(발생 시). 상시 숫자 2 = 카운터 금액 · 진행 표시 1개 |
| **홈 — 항목 행 1개** | — | **1** | 0 | 0 | 항목명 · 납입일 · 금액 1 · 상태 요소 **최대 1**. 배지 2개 동시 노출 금지 |
| **설정 `/settings`** | **6** | **2** | 0 | **0** | 숫자 2 = 목표 금액 · 시작 잔액. 버전 문자열은 제외 |
| **담기 `/add`** | **2** | **1** | 0 | **1** | 블록 2 = 입력 폼 · 계획 대비 요약. 숫자 1 = 입력 즉시 반영되는 결과 **하나**(`1억까지 +N%` 또는 `N원 남음` 중 택1) |
| **`/detail`** | **3** | 섹션당 **2** | 섹션당 **1** | **0** | 브리프 §3의 3섹션 상한 |
| **온보딩 스텝 1개** | **1** | **1** | 0 | **1** | 한 스텝에 질문 1개 (§4의 분기 구조) |

**운용 규칙**

1. **상한은 목표가 아니라 천장이다.** 4가 상한인 화면을 3으로 만들었다면 남은 1칸은 비워둔다 — 채워야 할 자리가 아니다.
2. **새 요소를 넣으려면 같은 화면에서 하나를 뺀다.** 예산을 넘긴 PR은 머지하지 않는다.
3. **상한을 올리려면 이 문서를 먼저 고친다.** 코드가 문서를 앞서지 않는다.
4. **조건부 노출로 회피하지 않는다.** "평소엔 안 보이니까 괜찮다"는 §9의 "서랍에 넣지 않는다"와 같은 회피다.

## 3. No-go — 브리프가 막지 않은 것들

**이 목록에 있는 것을 만들자는 제안이 나오면, 제안이 아니라 이 문서를 고치는 논의부터 한다.**

### 3.1 숫자

| # | 만들지 않는 것 | 금지 사유 |
| --- | --- | --- |
| N-01 | **두 번째 진행률** (카운터 외의 %·게이지·바) | %가 하나라도 더 있으면 **어느 게 진짜인지 사용자가 판단해야 한다.** 1순위 위험 |
| N-02 | **"이번 달 남은 일 N건" 류의 할 일 카운터** | 자동 채움은 숙제를 없애기로 한 설계다(§4). 카운터가 숙제를 되살린다 |
| N-03 | **"남은 개월 수" 상시 표기** | 도달 예측은 `/detail`이 답한다. 홈에 두면 **줄어드는 숫자**가 생겨 카운터의 "절대 줄지 않는다"(§11)와 톤이 어긋난다 |
| N-04 | **이번 달 페이스·달성률 지표** | 계획 대비 어긋남은 **3개월 연속 20% 이탈일 때만** 묻기로 했다(§4). 상시 지표는 그걸 매달 잔소리로 바꾼다 |
| N-05 | **평균·최고·최저 같은 통계 파생 수치** | 숫자를 움직이지 않는다. 1억을 올리는 건 매달의 납입이다 |

### 3.2 시각화

| # | 만들지 않는 것 | 금지 사유 |
| --- | --- | --- |
| N-06 | **홈의 차트** (스파크라인·미니 그래프 포함) | 차트는 `/detail` 3섹션 안에서만. 홈에 두면 카운터가 두 번째 요소가 된다 |
| N-07 | **히트맵 / 잔디 격자 / 12칸 달력** | 빈 칸이 곧 실패 표시라 **"못 채운 달을 벌주는 화면"**이 된다(§7) |
| N-08 | **같은 값의 두 번째 표현** | 진행률을 숫자·바·도토리로 동시에 그리지 않는다. 하나만 고른다 |
| N-09 | **회전/자동 전환 문구** (인사이트 캐러셀·팁 슬라이더) | 숫자를 움직이지 않으면서 화면에 상주하고, 매번 다른 말을 해 신뢰를 깎는다 |
| N-10 | **파이/도넛 구성 차트** | 유형을 안 묻기로 한 이상 나눌 축이 없다 |
| N-11 | **빈 상태를 채우는 장식 블록** (샘플 데이터·예시 카드) | B(처음 모으는 사람)의 홈은 **계획으로** 찬다(§4). 가짜로 채우지 않는다 |

### 3.3 문구·연출

| # | 만들지 않는 것 | 금지 사유 |
| --- | --- | --- |
| N-12 | **응원·독려 문구의 상시 노출** | 축하는 **사건이 있을 때만** 온다(§7). 상시 응원은 축하의 값을 떨어뜨린다 |
| N-13 | **부정 프레이밍 문구·색** ("안 넣으셨네요", 빨강 미달, D-day) | 회색·무표정으로 둔다. "이번 달은 빼둘게요"(§4) |
| N-14 | **홈 상시 공유 버튼** | 잘했다고 느낀 직후에만 조용히 내민다(§8) |
| N-15 | **투자 조언·교육 문구** | 가르치지 않는다(§7) |

### 3.4 구조

| # | 만들지 않는 것 | 금지 사유 |
| --- | --- | --- |
| N-16 | **탭 3개 이상** | 홈·설정 2개로 확정(§3). 탭이 늘면 "한마디로 설명되는 앱"이 깨진다 |
| N-17 | **설정 안의 "고급 설정" 서랍** | 서랍은 삭제를 미루는 장치다. 남기거나 자른다 |
| N-18 | **필수 입력 필드 5개 이상** | 이름·금액·주기·시작 시점 4개로 확정(§6) |

## 4. 답이 필요한 질문 3건

세 건 모두 **홈 블록 예산 4칸을 넘기는 문제**라 와이어프레임을 그리기 전에 답이 필요하다.
내가 정하지 않았다.

### Q1. 홈에 "계획 대비 채움"을 보여주는가?

- **브리프 상태**: §6은 **담기 폼**에 `매달 100만원 중 60만원 채움 · 40만원 남음`을 확정했다. §3의 홈 구성 ①~④에는 **없다.**
- **왜 물어야 하나**: 홈 블록 4칸이 이미 꽉 차 있다(카운터·현황·목록·축하).
- **선택지**: (a) 홈에서 뺀다 — 담기 폼에서만 본다 / (b) `이번 달 현황` 블록 안의 한 줄로 흡수 (블록 4 유지, 숫자 +1) / (c) 5번째 블록을 허용한다

### Q2. 화면 안에서 금액을 가리는 기능을 유지하는가?

- **브리프 상태**: §8은 **공유** 시 금액 비노출만 다룬다. 화면 내 가리기는 **언급 없음.**
- **왜 물어야 하나**: 카운터가 홈의 1번 요소가 되면, 가리기 버튼은 **1번 요소를 지우는 버튼**이 된다. 기존 기능(`show_monthly_amount`)이 원래 무엇을 막으려 했는지(어깨너머 노출?) 확인돼야 판단이 선다.
- **선택지**: (a) 삭제 / (b) 유지하되 카운터에는 적용하지 않는다 / (c) 유지 + 카운터에도 적용

### Q3. 브랜드 스토리를 홈에 두는가?

- **브리프 상태**: §9는 "존치 · 내용 교체"라고만 적혀 있고 **어디에 두는지는 없다.** 설정에도 같은 진입이 이미 있다.
- **왜 물어야 하나**: 홈에 두면 5번째 블록이 된다.
- **선택지**: (a) 홈에서 뺀다 — 설정 진입만 남긴다 / (b) 홈에 유지하고 블록 예산을 5로 올린다

> [!note] 묻지 않기로 한 것
> **알림함 UI · 항목 순서 정렬 · 보관한 목표** — 앞의 둘은 요소가 아니라 인터랙션·플래그라 예산 대상이 아니고
> 구현 시점에 정하면 된다. 보관한 목표는 목적 삭제에 딸려 자동으로 사라진다.
>
> **`/detail` 3섹션 중 나머지 2개**는 [01-brief.md §11](01-brief.md)이 이미 미결로 잡아둔 항목이라 여기서 중복해 묻지 않는다.

## 5. 조사에서 나온 사실 3건

제약과 별개로, 화면을 훑다가 확인된 것이다. **일정과 문서 정합성에 영향이 있어 남긴다.**

| # | 사실 | 영향 |
| --- | --- | --- |
| 1 | **브리프 §3의 홈 구성 ①②④가 코드에 아예 없다.** 1억 카운터·자동 채움·완주 축하 모두 미구현이고, ②는 현재 *수동 체크*(`GoalGroupItemRow.tsx`)로 방향이 정반대다 | **v2 홈은 축소가 아니라 백지 구현이다.** 9/7 구현 주차 산정에 반영돼야 한다 |
| 2 | **브리프 내부 불일치** — §9 표는 "통계 23섹션", §3은 "지금 9섹션". 실측은 **탭 3 × 섹션 3 = 9섹션**(`StatsContent.tsx`). 23은 근거를 못 찾았다 | §9 표의 숫자를 9로 고쳐야 한다 |
| 3 | **전역 시작 잔액·목표 금액이 스키마에 없다.** `goals.external_amount`·`target_amount`는 **목적 단위**라 목적을 지우면 같이 사라진다 | 브리프 §3의 설정 항목("목표 금액 · 시작 잔액")은 **스키마 작업**이다. Phase 2.5(9/1~9/6) 범위에 들어가는지 확인 필요 |

## 6. 쓰는 법

- **새 요소 제안이 올라오면** §3의 N-01~N-18과 §2의 상한을 먼저 대조한다. 걸리면 제안이 아니라 이 문서를 고치는 논의부터 한다.
- **판정이 애매하면** 맨 위의 단일 기준 한 문장으로 되돌아간다. 그 문장에 답하지 못하는 요소는 만들지 않는다.
- **"일단 숨기고 나중에"는 이 문서에 없는 선택지다.**
