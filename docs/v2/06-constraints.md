# v2 화면 제약 — No-go 목록과 요소 예산

> [!abstract] 이 문서가 존재하는 이유
> 화면에 요소가 불어나는 것은 취향 문제가 아니라 **구조적으로 그렇게 되게 돼 있다.**
> 사람은 "개선하라"는 요구를 받으면 **더하기만 떠올리고 빼기는 거의 떠올리지 못한다.**
> LLM은 학습 데이터의 평균(대시보드 + 카드 + 차트)으로 수렴하면서 **"도움이 되어 보이는 것"을 최적화**해
> 요청하지 않은 요소까지 채워 넣는다.
>
> **프롬프트로는 안 막힌다.** 매번 "간결하게"라고 써도 다음 턴이면 다시 늘어난다.
> 그래서 **문서화된 상한과 금지 목록**으로 막는다. 이 문서는 취향의 기록이 아니라 **가드**다.

**판정 기준은 하나뿐이다.**

> **"이 요소가 없으면 사용자가 '1억까지 얼마나 왔고 오늘 뭘 해야 하는지'를 알 수 없게 되는가?"**

- **필수** — 없으면 위 질문에 답할 수 없다
- **판단 필요** — 근거가 갈리거나 브리프에 답이 없다 → §5의 질문으로 남긴다
- **불필요** — 없어도 위 질문에 답할 수 있다

**"숨기기 / 설정으로 이동 / 나중에 처리"는 판정에 없다.** 남기거나 자른다 (브리프 §9의 "서랍에 넣지 않는다").

## 2. 브리프가 요구하는 것 vs 지금 있는 것

브리프 §3 기준. **"브리프에 없음"은 추론으로 채우지 않고 없다고 적었다.**

### 2.1 브리프가 요구하는데 지금 없는 것

| 브리프 요구 | 출처 | 현재 상태 |

### 3.1 필수 — 없으면 "얼마나 왔나 / 오늘 뭘 하나"에 답할 수 없다

| 요소 | 왜 필수인가 |
| --- | --- |
| 1억 카운터 금액 (신규) | **"얼마나 왔나"에 직접 답하는 유일한 요소.** 브리프 §11이 카운터를 원금 하나로 정의했다 |
| 이번 달 현황 — 채워짐/안 채워짐 (신규) | **"오늘 뭘 하나"에 답한다.** 자동 채움이라 사용자가 할 일은 "틀리면 내리기" 하나이고, 그 대상이 여기다 |
| 적립 항목 목록: 항목명 (H-13) | 무엇이 채워졌는지 식별하는 최소 단위 |
| 적립 항목 목록: 월 납입액 (H-15, 원 단위만) | 카운터가 왜 그 속도로 오르는지의 근거 |
| 적립 항목 목록: 납입일 (H-14) | "오늘 뭘 하나"의 시점. 자동 채움의 트리거이기도 하다 |
| 항목 행의 상태 요소 **1개** (H-16~H-19 중 하나) | 채워졌는지 아닌지. **단, 자동 채움 후에는 "내리기"만 남으므로 상태 요소는 행당 1개를 넘지 않는다** |
| `적립 항목 담기` 진입 (H-25 또는 대체) | 항목이 없으면 카운터가 안 오른다 |

| 앱바 로고 (H-01) | 판정 기준 밖이지만 앱 식별. **요소 예산에서는 카운트하되 상한 대상 아님** |

### 4.2 (b) 화면별 요소 예산

**세는 단위**

- **블록** = 시각적으로 구분되는 카드·섹션·바 1개 (`bg-card` 껍데기, 구분선으로 나뉜 영역, 고정 바)
- **숫자** = 화면에 렌더링되는 수치 1개 (금액·%·개월·건수·날짜의 숫자 부분). 목록의 반복 항목은 **행당 상한**으로 따로 센다
- 상한은 **동시에 보이는 최대치**다. 조건부로만 뜨는 것도 뜨는 순간엔 카운트된다

| 화면 | 블록 상한 | 숫자 상한 | 차트 | primary 버튼 | 비고 |
| --- | --- | --- | --- | --- | --- |
| **홈 `/`** | **4** | **2 + (항목행당 1)** | **0** | **1** | 블록 4 = 카운터 · 이번 달 현황 · 항목 목록 · 축하(발생 시). 상시 숫자 2 = 카운터 금액 · 진행 표시 1개. 항목 행은 금액 1개만 |
| **홈 — 항목 행 1개** | — | **1** | 0 | 0 | 항목명 · 납입일 · 금액 1 · 상태요소 **최대 1**. 배지 2개 동시 노출 금지 |
| **설정 `/settings`** | **6** | **2** | 0 | **0** | 섹션 6개 상한. 숫자 2 = 목표 금액 · 시작 잔액. 버전 문자열은 숫자에서 제외 |
| **담기 `/add`** | **2** | **1** | 0 | **1** | 블록 2 = 입력 폼 · 계획 대비 요약. 숫자 1 = 입력 즉시 반영되는 결과 1개(`1억까지 +N%` 또는 `N원 남음` 중 **하나**) |
| **`/detail`** | **3** | **섹션당 2** | **섹션당 1** | **0** | 브리프 §3의 3섹션 상한. 섹션마다 차트 1 + 그 차트를 설명하는 숫자 2까지 |
| **온보딩 스텝 1개** | **1** | **1** | 0 | **1** | 한 스텝에 질문 1개 (§4의 분기 구조) |

**예산 운용 규칙**

1. **상한은 목표가 아니라 천장이다.** 4가 상한인 화면을 3으로 만들었다면 남은 1칸은 비워둔다 — 채워야 할 자리가 아니다.
2. **새 요소를 넣으려면 같은 화면에서 하나를 뺀다.** 예산 초과 상태의 PR은 머지하지 않는다.
3. **상한을 올리려면 이 문서를 먼저 고친다.** 코드가 문서를 앞서지 않는다.
4. **조건부 노출로 상한을 회피하지 않는다.** "평소엔 안 보이니까 괜찮다"는 §9의 "서랍에 넣지 않는다"와 같은 회피다.
5. **`판단 필요`로 남은 요소는 상한 안에서만 살릴 수 있다.** Q1~Q6의 답이 무엇이든 위 상한은 그대로다.

## 5. 결정이 필요한 질문 (내가 정하지 않았다)

각 질문에 **결정에 필요한 정보**를 같이 적었다. 답이 나오면 §3.3의 항목이 필수 또는 불필요로 이동한다.

### Q1. 홈에 "계획 대비 채움"을 보여주는가?

- **대상**: 현재 `이번 달 적립금액` 카드 (H-32~H-35)
- **브리프 상태**: §6은 **담기 폼**에 `매달 100만원 중 60만원 채움 · 40만원 남음`을 확정했다. §3의 홈 구성 ①~④에는 **없다.**
- **결정에 필요한 정보**: 홈 블록 예산이 4칸(카운터·현황·목록·축하)으로 꽉 차 있다. 이걸 넣으려면 **5번째 블록을 허용**하거나 **`이번 달 현황` 블록 안에 흡수**해야 한다.
- **선택지**: (a) 홈에서 뺀다 — 담기 폼에서만 본다 / (b) `이번 달 현황` 블록 안의 한 줄로 흡수 (블록 4 유지, 숫자 +1) / (c) 5번째 블록 허용

### Q2. 화면 안에서 금액을 가리는 기능을 유지하는가?

- **대상**: H-33~H-35, S-16
- **브리프 상태**: §8은 **공유** 시 금액 비노출만 다룬다. 화면 내 가리기는 **언급 없음.**
- **결정에 필요한 정보**: 카운터가 홈의 1번 요소가 되면 가리기는 **1번 요소를 지우는 버튼**이 된다. 원래 이 기능이 무엇을 막으려고 있었는지(어깨너머 노출?) 도입 의도를 확인해야 판단이 선다.
- **선택지**: (a) 삭제 — 버튼 2개와 코인 아이콘 4개가 함께 빠진다 / (b) 유지하되 카운터에는 적용 안 함 / (c) 유지 + 카운터에도 적용

### Q3. 브랜드 스토리 카드를 홈에 상시로 두는가?

- **대상**: H-36~H-39
- **브리프 상태**: §9는 "FAQ · 브랜드 스토리 — **존치 · 내용 교체**". **어디에 두는지는 안 적혔다.** 설정에도 같은 진입(C-08)이 이미 있다.
- **결정에 필요한 정보**: 홈 블록 4칸에 브랜드 스토리는 없다. 홈에 두려면 5번째 블록이 된다. 이 카드의 실제 탭률(GA)이 있으면 바로 정리된다.
- **선택지**: (a) 홈에서 뺀다 — 설정 진입만 남긴다 / (b) 홈에 유지하고 블록 예산을 5로 올린다

### Q4. 알림함 UI를 v2에서 켜는가?

- **대상**: H-02 (현재 `SHOW_NOTIFICATION_INBOX = false`로 꺼져 있다)
- **브리프 상태**: §9는 "알림 7종 — v2.0.0에서 손대지 않음 · 문구만 1억 기준으로 고친다". **인박스 UI는 언급 없음.**
- **결정에 필요한 정보**: 자동 채움으로 홈에서 할 일이 사라지면 알림이 매달 루프의 **유일한 시작점**이 된다(§4). 그때 알림 내역을 앱 안에서 다시 볼 필요가 있는지가 관건이다.
- **선택지**: (a) 꺼진 채로 둔다 — 코드도 함께 뺀다 / (b) 켠다 (앱바에 요소 +1) / (c) 꺼진 채 코드만 남긴다 → **이건 "서랍"이라 §9 원칙상 권하지 않는다**

### Q5. 항목 순서를 사용자가 바꿀 수 있어야 하는가?

- **대상**: H-31 (목적 정렬 H-30은 목적 삭제로 자동 소멸)
- **브리프 상태**: **언급 없음.**
- **결정에 필요한 정보**: 목적 카드가 사라지면 항목 목록이 홈의 유일한 리스트가 된다. 항목 개수 분포(현재 사용자 평균 몇 개인지)를 알면 판단이 선다 — 3~4개면 정렬이 필요 없고, 10개 이상이면 필요하다.
- **선택지**: (a) 삭제 — 납입일 순 고정 / (b) 유지

### Q6. `보관한 목표`(설정)를 어떻게 하는가?

- **대상**: C-05, `app/settings/archived-goals`
- **브리프 상태**: §9는 목적 삭제를 확정했지만 **보관함은 명시 판정이 없다.** §9의 "데이터는 지우지 않는다"는 **테이블** 이야기이지 화면 이야기가 아니다.
- **결정에 필요한 정보**: 보관함에 실제로 데이터가 들어 있는 사용자가 있는지. 없으면 화면만 지우면 끝난다.
- **선택지**: (a) 화면 삭제 — 목적 삭제에 함께 딸려간다 / (b) 이관 기간 동안만 남긴다 → **기한을 명시하지 않으면 서랍이 된다**

### 브리프가 이미 미결로 표시한 것 (여기서 새로 묻지 않는다)

`01-brief.md §11`의 미결 #5 — **`/detail` 3섹션 중 나머지 2개.** 자산 추이(원금)만 확정.

## 6. 이 문서를 쓰는 법
