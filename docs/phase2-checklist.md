## 1. 기능 존치 / 삭제 판정 (8/25 ~ 8/27)

판정 기준은 하나 — **"1억 모으기를 돕는가."**

- [ ] **납입 연기** — 1억엔 마감일이 없어 "빠뜨림" 개념이 사라진다. 지우려면 **연속 기록을 안 보여주는 것까지** 같이 정해야 한다
- [ ] **소급 기록** — 유틸 12곳에 퍼져 있음. "예전부터" 질문으로 흡수 가능한가
- [ ] **토리 키우기** — 파일 34개. 진입 경로가 없어 사용자에겐 이미 없는 기능
- [ ] **목적 프리셋** — 목적 계층이 사라지면 근거도 사라지는가
- [ ] **FAQ · 브랜드 스토리** — 설정 2뎁스 안쪽, 계측 0건
- [ ] **알림 7종을 몇 개로 줄일 것인가** — 계측이 0건이라 판단 근거가 없다
- [ ] **`/design-system`, `/notifications?demo=1`** — 개발용 경로 정리

## 2. 입력 플로우 (8/28 ~ 9/1)

- [ ] **평가금액 변동을 1억 카운터에 반영할 것인가, 원금만 셀 것인가** ← 제일 큰 결정
- [ ] 만기일이 **있는 항목과 없는 항목**을 같은 폼에서 어떻게 받는가
- [ ] 이미 넣던 항목의 **과거 회차를 어디까지** 받을 것인가
- [ ] 미국 종목의 **환율을 언제 시점으로** 고정하는가
- [ ] 주수 · 시장이 붙어도 **"필수 4개"가 안 깨지는지** 검증
- [ ] 적립 항목 1개 추가에 드는 **동작 수를 숫자로 확정** (지금 안: 타이핑 2 + 탭 4)

## 3. 자산 연결 (리서치 결과 나온 뒤)

- [ ] 다시 불러오기를 **자동으로 돌릴 것인가**, 사용자가 누를 때만 할 것인가
- [ ] 금액이 **줄었을 때**(출금 · 손실) 1억 카운터를 내릴 것인가
- [ ] 불러온 항목과 수기 항목이 **같은 계좌**일 때 중복을 어떻게 잡는가
- [ ] 연동 시 **개인정보 처리방침 · 약관 개정 범위**
- [ ] 연결 인증이 풀렸을 때 **어떻게 알릴 것인가**

## 4. 화면 내용 (9/2 ~ 9/6)

- [ ] **`/detail` 3섹션의 정확한 내용** — 자산 추이가 원금인가 평가액인가
- [ ] **지난 달 소급 체크**를 허용할 것인가 — 되면 정직한 기록, 안 되면 숫자가 굳는다
- [ ] **도달 예측을 무엇으로 계산**하는가 — 최근 3개월 평균? 온보딩에서 받은 월 적립 목표액? **둘은 자주 다르다**
- [ ] 월 적립 목표액과 **실제 적립액이 어긋날 때** 어떻게 말할 것인가 ("15만원 덜 넣고 있어요")
- [ ] 항목 상세의 **"건너뜀"** 표기를 남길 것인가 (납입 연기의 후신)
- [ ] **탈퇴 시 무엇이 지워지는지** 명시 문구
